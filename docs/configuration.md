# Environment reference

Copy configuration from [`.env.example`](../.env.example) or run `npm run setup` once. Never commit `.env`, keys, database dumps, or provider responses. `npm run setup` refuses to overwrite existing configuration. Next.js loads `.env`; worker and migration scripts use Node's `--env-file-if-exists=.env`. Restart web and worker after changes. Compose explicitly maps variables; the scanner receives only its token.

## Required infrastructure and authentication

| Variables                                                                                | Purpose                                                                                                              |
| ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `APP_URL`                                                                                | Canonical origin; HTTPS on servers, loopback in local development                                                    |
| `APP_DOMAIN`                                                                             | Hostname for the supplied Dokploy/Traefik override                                                                   |
| `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD`                                      | Database bootstrap; changing the password here does not rotate an existing database role                             |
| `DATABASE_URL`                                                                           | PostgreSQL URL for host processes; Compose constructs the internal URL                                               |
| `BETTER_AUTH_SECRET`                                                                     | Strong persistent authentication/encryption secret; generated by setup                                               |
| `SIGNUP_MODE`                                                                            | `open` (default) or `restricted`; independent of repository visibility and billing                                   |
| `ADMIN_EMAILS`                                                                           | Restricted signup allowlist and legacy migration owners; does not grant operator access                              |
| `DEV_AUTH_BYPASS`                                                                        | Local `next dev` with loopback only; production Compose forces `false`                                               |
| `OPERATOR_GITHUB_ID`                                                                     | Optional immutable numeric GitHub user ID for cross-workspace operator administration; empty grants nobody this role |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`                                               | GitHub App login credentials                                                                                         |
| `GITHUB_APP_ID`, `GITHUB_APP_SLUG`, `GITHUB_PRIVATE_KEY_BASE64`, `GITHUB_WEBHOOK_SECRET` | GitHub App review and signed webhook credentials                                                                     |
| `SCANNER_TOKEN`, `SCANNER_URL`                                                           | Authenticated private scanner endpoint; Compose supplies its internal URL                                            |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `EMAIL_FROM`      | Optional email-code login; default port 587, mandatory STARTTLS unless implicit TLS is selected                      |
| `DEV_DATABASE_PORT`, `DEV_SCANNER_PORT`                                                  | Optional loopback dependency ports for `compose.dev.yml`                                                             |

For a private self-hosted installation, set `SIGNUP_MODE=restricted` and your verified `ADMIN_EMAILS`. Public source code does not require open signup on your deployment. With open signup and free reviews, the operator bears provider costs; use restricted signup for personal instances.

## Models

| Variables                                                        | Purpose                                                                                   |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `LLM_BASE_URL`                                                   | HTTPS API root including `/v1`; defaults to OpenAI when generic configuration is selected |
| `LLM_API_KEY`, `LLM_MODEL`                                       | Provider key and exact available chat model identifier                                    |
| `LLM_FALLBACK_MODEL`                                             | Optional alternative on a detected NaN reasoning-only cutoff; no general error failover   |
| `LLM_TOKEN_PARAMETER`                                            | `max_tokens` (default) or `max_completion_tokens`, according to model support             |
| `NAN_BASE_URL`, `NAN_API_KEY`, `NAN_MODEL`, `NAN_FALLBACK_MODEL` | Legacy configuration family; used only when all generic connection fields above are empty |

Setting any nonempty `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, or `LLM_FALLBACK_MODEL` selects the entire generic family. Missing generic credentials do not fall back to NaN credentials. See [provider examples and protocol requirements](llm-providers.md).

## Optional payments

| `BILLING_ENABLED` | Behavior                                                                                                          |
| ----------------- | ----------------------------------------------------------------------------------------------------------------- |
| `auto` or unset   | Billing only when all five Creem fields below are nonempty; otherwise no subscription gate or checkout            |
| `false`           | Disable billing even with Creem fields present                                                                    |
| `true`            | Explicit paid operation; missing Creem setup blocks purchases and unpaid reviews rather than granting free access |

The five fields are `CREEM_API_KEY`, `CREEM_WEBHOOK_SECRET`, `CREEM_PLAN_PRODUCT_ID`, `CREEM_TOKEN_PRODUCT_ID`, and `CREEM_METER_ID`. `CREEM_TEST_MODE=true` is the sandbox default; explicitly set `false` for verified live operation. `BILLING_PROVIDER_TOKEN_BUDGET` defaults to 3 billion tokens; `BILLING_PROVIDER_PERIOD_START` is an optional ISO quota-period start, otherwise the current UTC month.

Use `BILLING_ENABLED=true` once offering a paid service, so an accidentally removed key cannot silently turn off enforcement. Disabled billing bypasses billing-ledger usage instrumentation and monetary/provider-budget enforcement, while source-size, timeout, scanner, and queue safety controls remain. The Statistics page still shows review results. Disabling billing does not cancel existing Creem subscriptions or erase accrued charges: settle usage and cancel subscriptions before switching a paid installation to free mode. Signed payment webhooks remain available for reconciliation when their secret is configured.

## Upgrading an existing operator deployment

The original code granted operator privileges to a fixed account. This version has no default operator. Set `OPERATOR_GITHUB_ID` to your independently verified numeric GitHub ID on both web and worker before upgrading. For the original Codelean operator this was `1257083`; other installations must use their own ID. Existing NaN settings need no change. Keep `BILLING_ENABLED=true` on existing paid deployments. Back up first; see [upgrade instructions](installation.md#7-upgrade-rollback-and-maintenance).
